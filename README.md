# Haylou LS02 Watch - Home Assistant Integration

This is a Home Assistant custom integration for the **Haylou Smart Watch 2 (LS02)**.

Requires Home Assistant **2026.5.0** or later.

## Features

- **Device Discovery**: Automatically discovers Haylou Smart Watch 2 devices via Bluetooth
- **Multi-Device Support**: Add multiple watches with custom names
- **Resilient Startup**: The integration loads even when Bluetooth is not ready at boot; connect, subscribe, and initialize run in a background retry loop
- **Device Tracker**: Track watch presence (`Home` / `Away`) using BLE connection and passive advertisements
- **Heart Rate**: Current heart rate plus min, max, and average statistics from the watch
- **Sleep Tracking**: Total, deep, and light sleep duration, segment list, and sleep start/end timestamps
- **Steps**: Daily step count from sport statistics
- **Battery Monitoring**: Watch battery level in percent
- **Weather Support**: Optionally push forecast from a Home Assistant weather entity to the watch
- **Watch Notifications**: Send text messages and alerts to the watch display
- **User & Watch Settings**: Configure units, user profile, screen timeout, step goal, and lift wrist mode from Home Assistant
- **Configurable Pairing PIN**: Set the 4-digit PIN used when pairing with the watch
- **Device Info**: Firmware version is shown on the device page when reported by the watch

## Installation

### Via HACS (Recommended)

1. Go to **HACS** → **Custom repositories**
2. Add the repository URL: `https://github.com/szupi/haylou_ls02_ha`
3. Select **Integration** as the category
4. Click **Install**
5. Restart Home Assistant

### Manual Installation

1. Download the latest release
2. Copy the `haylou_ls02` folder to `<config>/custom_components/`
3. Restart Home Assistant

## Configuration

### Adding a Haylou Watch

1. Go to **Settings** → **Devices & Services**.
2. Click **Add Integration** and search for **Haylou LS02**.
3. Choose how to find the watch:
   - **Scan for Haylou Watch**: Automatically finds nearby Haylou Smart Watch 2 devices.
   - **Enter device address manually**: Use this if the watch is not discovered automatically.
4. Enter a friendly name for the watch.
5. Optionally select a Home Assistant weather entity. If no weather source is selected, weather data will not be sent to the watch.
6. Enter the pairing PIN used by the watch. The default is `1234`; use the same PIN after Home Assistant restarts or when reconnecting an already paired watch.
7. Review the watch and user settings:
   - Displayed time format: `12h` or `24h`
   - Distance unit: `Metric` or `Imperial`
   - User height, weight, age, and gender
   - Screen timeout, daily step goal, and lift wrist mode
8. Confirm the setup.

If Bluetooth is unavailable during setup or restart, entities are still created. The integration keeps retrying connect → subscribe → initialize in the background (with backoff from 2 seconds up to 30 seconds).

### Changing Settings Later

Open the integration **Configure** options to change the weather source (including removing it), pairing PIN, units, and user/watch settings. Changing the pairing PIN disconnects the watch and triggers an immediate reconnect with the new PIN.

### Multiple Devices

You can add multiple watches. Each appears as a separate device in Home Assistant with its own entities.

## Available Entities

Entity IDs are generated by Home Assistant from the configured watch name.

### Device Tracker

- **Tracker**: `Home` when the watch is connected or recently seen on Bluetooth; `Away` when it has not been detected for about 10 minutes.

### Sensors

**Heart rate & activity**

- **Heart Rate Current**: Latest heart rate in BPM (may become unavailable when no fresh reading exists).
- **Heart Rate Max** / **Min** / **Average**: Statistics from the watch; retain the last value across brief data gaps.
- **Steps**: Step count reported by the watch.
- **Battery Level**: Battery percentage.

**Sleep** (synced from the watch after a successful connection)

- **Sleep Segments**: Total sleep duration in minutes (`duration` device class). Attribute `periods` lists all segments (`start`, `type`, `duration`).
- **Deep Sleep** / **Light Sleep**: Duration in minutes for each stage. Attribute `periods` lists only matching segments.
- **Sleep Start** / **Sleep End**: Timestamps (`timestamp` device class) of the first segment start and the end of the last segment (`unknown` until sleep data is available).

**Diagnostics**

- **Connection Status**: BLE state (`connected`, `connecting`, `disconnected`).
- **Weather Source**: Temperature from the configured weather entity (diagnostic; empty when no source is configured).

### Selects

- **Displayed Time Format**: `12h` or `24h`.
- **Distance Unit**: `Metric` or `Imperial`.
- **User Gender**: `Male` or `Female`.
- **Lift Wrist Mode**: `On` or `Off`.

### Numbers

- **User Height**: Centimeters (`100`–`220`).
- **User Weight**: Kilograms (`40`–`200`).
- **User Age**: `5`–`120`.
- **Screen Time**: Screen timeout in seconds (`3`–`30`).
- **Daily Steps Goal**: `100`–`65000`.

## Services

### send_message

Send a text message to the watch display.

```yaml
service: haylou_ls02.send_message
data:
  message: "Hello from Home Assistant!"
  message_type: "generic"  # or: phone_call, whatsapp, email, facebook, twitter, etc.
```

Optional `device_address` targets a specific watch when multiple are configured.

**Supported message types:**

- `phone_call`, `qq`, `wechat`, `generic`, `facebook`, `twitter`, `whatsapp`, `skype`, `messenger`, `hangouts`, `line`, `linkedin`, `instagram`, `viber`, `kakaotalk`, `vk`, `snapchat`, `googleplus`, `email`, `flickr`, `tumblr`, `pinterest`, `youtube`

## How It Works

This integration uses Home Assistant's Bluetooth stack and **Bleak** (via `bleak_retry_connector`) to talk to the watch over BLE.

1. On load, it attempts to connect, subscribe to notifications, and initialize the watch (pairing, time, units, user info, battery, firmware, sport stats, heart rate, sleep).
2. A background task keeps the session alive and reconnects with exponential backoff if the link drops or startup failed.
3. Notifications are handled on three characteristics:
   - General notify (`000033f2…`): battery, firmware, heart rate, sport stats, sleep init/end markers
   - Data2 notify (`00006002…`): extended heart rate and sleep init/end
   - Sleep notify (`00006102…`): sleep segment payloads
4. Coordinator data drives all entities; select/number changes are written back to the watch when connected.

## Troubleshooting

### Device not discovered

- Ensure the watch is powered on and in range
- Confirm the Home Assistant host has working Bluetooth
- Check logs for Bluetooth-related errors

### Connection issues at startup or after restart

- Entities may show `disconnected` until the retry loop succeeds; this is expected if Bluetooth was not ready at boot
- Bring the watch closer to the host
- Verify the pairing PIN matches what the watch expects (same PIN as in integration options)
- Changing the PIN in options forces a disconnect and reconnect; the watch may need a factory reset if the PIN no longer matches a prior pairing

### Sleep data missing

- Sleep is requested during watch initialization after a successful connection
- Enable debug logging for the integration to see `HaylouSleep` parse details in the log

### Weather not updating on the watch

- A weather source must be selected in integration options
- The source entity must expose temperature (and forecast where supported)
